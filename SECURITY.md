# Security Policy

## Supported Versions

Security updates are applied to the latest release series on the `main` branch.

| Version | Supported          |
| ------- | ------------------ |
| Latest (`0.x`) | :white_check_mark: |
| `< 0.8.0` | :x:                |

## Security & Integrity Invariants

1. **Declarative Bounds & Recursion Limits**: Nix `flake.lock` and Kubernetes manifest parsers enforce strict depth limits (default max depth: 64) and streaming size ceilings (10MB payload ceiling, 1000 documents per stream) to mitigate parser recursion and resource exhaustion attacks.
2. **Kubernetes & CNI Zero-Trust Enforcement**: Ingress analyzers and CNI policy verifiers proactively detect unanchored URI regex rewrites (CVE-2026-21801), Lua/command snippet injections (CVE-2023-5044), 0.0.0.0/0 egress data leaks, and unauthenticated infrastructure port exposures.
3. **Memory Hygiene & Zero Secret Exposure**: Threat feed caches, API tokens, and internal vulnerability buffers are kept ephemeral in memory with zero plaintext secrets written to logs, disk, or terminal output.
4. **Pure Evaluation & Hash Verification**: Nix input locks require strict revision and `narHash` integrity validation to detect tampered upstream git references and unauthenticated binary cache overrides.
5. **Input Sanitization & Safe Deserialization**: All untrusted JSON and YAML feeds pass through strict schema validation with bounded streaming before evaluating threat signatures.
6. **Briefing Sanitization & Path Traversal Guard**: Automated Markdown briefing generators sanitize output directories and file paths (`filepath.Clean` and `filepath.Base`), preventing directory traversal when persisting reports. Telemetry aggregations strictly enforce deterministic sorting and bounds checking.
7. **Declarative Policy Synthesis Integrity & Schema Conformance**: Synthetic Falco runtime rules and OPA Gatekeeper ConstraintTemplates enforce sanitized YAML escaping, strict Rego syntax constraints, and schema conformance to prevent policy injection or admission bypass vulnerabilities.
8. **SARIF & JSON Security Audit Exporter Integrity**: Exporters for OASIS SARIF v2.1.0 and structured JSON enforce strict schema validation, defend against directory traversal (`filepath.Clean`), guarantee deterministic rule index mapping, and prevent arbitrary field injection in CI/CD and GitHub Code Scanning pipelines.
9. **Bare-Metal eBPF Telemetry Isolation & Bounds Protection**: Kernel telemetry probes enforce thread-safe multi-node channel aggregation (`sync.RWMutex`), bounded event buffers (10,000 snapshot ceiling), drop-on-saturation ring-buffer ergonomics, and fixture file bounds protection (10MB ceiling) to prevent memory amplification and denial-of-service in high-throughput node clusters.
10. **Rook Ceph Distributed Storage Integrity & Volume Safeguards**: Ceph declarative scanners and BlueStore anomaly detectors enforce strict payload limits (10MB manifests, 5MB telemetry), intercept unencrypted wire transport (`msgr2` disabled) and plaintext raw NVMe/SSD disks, mandate odd-numbered monitor quorums with cross-node anti-affinity, reject unsafe ReadWriteMany (RWX) multi-attaches on RBD block PVCs, and continuously correlate Linux 6.12 async direct I/O metadata desync threats (CVE-2026-15509).
11. **WireGuard Mesh Network Cryptographic Key Rotation & Posture Invariants**: WireGuard configuration scanners and mesh reconcilers enforce strict bounds limits (10MB manifest ceiling, 5MB telemetry payload), intercept world-readable plaintext private keys (`privateKey`) and hardcoded pre-shared keys in `/nix/store` (CVE-2026-31048), mandate periodic 90-day cryptographic keypair rotation with 60-day warning windows, mask cryptographic key material in all logs and outputs (zero plaintext secret exposure), detect allowedIPs subnet overlaps and traffic hijacking collisions, verify symmetric Pre-Shared Keys (PSK) for post-quantum defense-in-depth, and flag unmanaged peers or dormant handshakes (> 24h).
12. **CIS Kubernetes Benchmark & Control Plane Hardening Invariants**: Declarative CIS benchmark validators inspect NixOS systemd unit definitions and Kubernetes component configurations against CIS Benchmark Section 1 (API Server, Controller Manager, Scheduler), Section 2 (etcd), and Section 4 (Kubelet). Scanners strictly enforce memory ceilings (10MB manifest limit, 10,000 line scan bounds), disallow unauthenticated anonymous access (`--anonymous-auth=false`), close open metric endpoints (`--read-only-port=0`), enforce least-privilege authorization (`Node,RBAC` and `Webhook`, rejecting `AlwaysAllow`), require mutual TLS for all control plane and etcd communications, disallow insecure `auto-tls`, disallow static token files (`--token-auth-file`), restrict non-loopback bindings on internal telemetry ports, and synthesize declarative NixOS modules (`nixos-cis-hardening.nix`) ensuring automated remediation.
13. **Kubernetes Gateway API & EnvoyFilter Route Threat Radar Invariants**: Gateway API analyzers and EnvoyFilter security auditors enforce strict streaming memory limits (10MB manifest ceiling, 20,000 scan lines), mandate cross-namespace `ReferenceGrant` validation to prevent untrusted tenant workloads from hijacking privileged backend services across namespace boundaries (CVE-2026-44219), disallow insecure plaintext HTTP listeners without TLS termination or redirect, detect unsafe URLRewrite path traversal sequences (`..` and `//`), intercept identity header spoofing in `RequestHeaderModifier` (`X-Remote-User`, `X-Forwarded-User`, `X-Authenticated-Groups`), enforce granular gRPC method restrictions rejecting catch-all admin wildcards, guard sensitive control plane ports (etcd 2379, kube-apiserver 6443, datastore ports) from raw TCPRoute forwarding, detect dangerous Lua script injections (`os.execute`, `io.popen`, `loadstring`, `require os/io`) in EnvoyFilter proxies, prevent filter chain order bypasses (`INSERT_BEFORE` relative to `jwt_authn`, `istio.authn`, `rbac`), and block EnvoyFilter modifications that disable downstream mutual TLS client certificate verification.
14. **Confidential Computing & Measured Boot Attestation Invariants**: Attestation verifiers and declarative NixOS scanners enforce strict bounds limits (10MB manifest ceiling, 10MB attestation telemetry payload ceiling, 20,000 scan lines), verify AMD SEV-SNP (`mem_encrypt=on kvm_amd.sev=1`) and Intel TDX (`intel_iommu=on kvm_intel.tdx=1`) hardware memory encryption enforcement, mandate TPM 2.0 PKCS#11 integration (`security.tpm2.enable = true;`), enforce Lanzaboote / systemd-boot Unified Kernel Image (UKI) cryptographic signing, verify TPM 2.0 PCR quotations (PCR 0 firmware, PCR 7 Secure Boot policy, PCR 8 kernel cmdline, PCR 9 initrd/kernel binary, PCR 11 UKI closure digest), reject remote attestation reports with debug mode enabled (`debug_mode: true`), flag expired attestation tokens (> 24 hours), and detect measurement desynchronization or tampering between declarative Nix store paths and runtime hardware measurements (CVE-2026-51204).
15. **Multi-Cluster Fleet Synchronization & OIDC Federated Token Invariants**: Multi-cluster fleet scanners and GitOps reconcilers enforce defensive ceilings (10MB manifest ceiling, 10MB telemetry payload ceiling, 20,000 scan lines, 100 clusters per fleet), audit multi-tenant RBAC permissions to disallow wildcard verbs/resources (`*`), prevent privilege escalation via uncontained `bind` or `escalate` verbs, reject `impersonate` verbs without explicit `resourceNames` white-lists, prevent cluster-wide reading of `secrets` across tenant boundaries, prohibit `cluster-admin` bindings to broad unauthenticated/authenticated subject groups (`system:authenticated`, `system:unauthenticated`), enforce short-lived OIDC federated identity token lifetimes (maximum 24-hour ceiling), reject insecure OIDC signing algorithms (`none`, symmetric HMAC `HS256`, mandating asymmetric RS256/ES256), require verified `audience` and `issuer` claim restrictions, flag stale OIDC signing keys exceeding 90 days, mandate automated self-healing (`selfHeal: true` in ArgoCD, `prune: true` in Flux) to eliminate unmonitored configuration drift, require immutable commit SHA or release tag pinning in GitOps source repositories, disallow wildcard destination clusters (`server: "*"`), and continuously correlate runtime fleet synchronization desynchronization and health degradation across geographically distributed clusters (CVE-2026-60114).
16. **Zero-Trust Microsegmentation & SPIFFE/SPIRE Workload Attestation Invariants**: Workload identity validators and Cilium policy synthesizers enforce strict defensive bounds (10MB manifest ceiling, 5MB telemetry payload, 20,000 scan lines, 1000 SVID ceiling), validate SPIFFE ID URI syntax (`spiffe://<trust-domain>/<path>`), reject unauthorized foreign trust domains lacking explicit SPIFFE federation relationships, enforce short-lived ephemeral X.509 SVID lifespans (maximum 24-hour ceiling), detect expiring SVIDs lacking adequate renewal buffers (< 15 minutes remaining), disallow permissive wildcard selectors (`k8s:ns:*`, wildcard service accounts) in SPIRE registration entries, audit SPIRE agent admin UNIX domain sockets against world-writable or uncontained permissions, enforce mutual TLS authentication (`authentication.mode: required`) and `io.spiffe.id` label matching in CiliumNetworkPolicy ingress rules, mandate baseline default-deny microsegmentation posture across workload namespaces, reject obsolete or weak cryptographic key algorithms in SVID certificates (RSA < 2048, SHA-1), and actively correlate threat intelligence feeds against workload attestation bypass vectors (CVE-2026-67210).
17. **Software Bill of Materials (SBOM) & In-Toto Supply Chain Attestation Invariants**: Software Bill of Materials parsers and In-Toto provenance verifiers enforce strict defensive ceilings (15MB SBOM manifest ceiling, 10MB attestation payload ceiling, 10,000 package count limit, 5,000 delta comparison items limit), validate SPDX v3.0 and CycloneDX v1.6 schema specifications, require cryptographic Subject digest matching against binary build outputs (CVE-2026-71044), verify SLSA Level 3 hermetic and reproducible build parameters, disallow unpinned or mutable dependency references (e.g. `latest`, branch refs lacking commit SHAs or `narHash`), reject unverified or missing cryptographic signatures, detect unauthorized runtime package injections / shadow binaries, and flag version drift between GitOps declarations and active cluster runtime states.
18. **Hardware Security Module (HSM) & PKCS#11 Envelope Encryption Invariants**: EncryptionConfiguration parsers, PKCS#11 URI scanners, and KMS v2 telemetry monitors enforce strict memory limits (10MB manifest ceiling, 5MB telemetry payload, 5,000 key metadata ceiling), mandate KMS v2 (`apiserver.config.k8s.io/v1`) with local unix domain socket transport (`unix:///...`), reject insecure etcd configurations placing unencrypted `identity` providers ahead of KMS providers, disallow single-point-of-failure configurations lacking fallback providers, detect and redact plaintext PKCS#11 PINs (`pin-value=`) embedded in declarative manifests, enforce cryptographic memory zeroization for authentication tokens, reject deprecated cipher suites (DES, 3DES, AES-CBC-128, RSA-1024), mandate Key Encryption Key (KEK) rotation under 90 days, audit AWS Nitro Enclave isolation parameters, and continuously detect session handle leaks and unsealed attestation quotes (CVE-2026-83190).
19. **Dynamic Kernel Runtime Threat Profiling & Syscall BPF Filter Invariants**: Kernel runtime telemetry profilers and declarative seccomp parsers enforce strict streaming bounds (10MB manifest ceiling, 5MB telemetry payload ceiling, 20,000 scan lines), mandate `securityContext.seccompProfile.type: RuntimeDefault` or hardened `Localhost` profiles, reject unconfined workload declarations (`type: Unconfined`), disallow container host namespace sharing (`hostPID: true`, `hostIPC: true`), audit elevated capabilities (`CAP_NET_RAW`, `CAP_SYS_ADMIN`, `CAP_SYS_MODULE`), detect high-privilege syscalls (`ptrace`, `process_vm_writev`, `kexec_load`, `reboot`, `pivot_root`, `init_module`), enforce mandatory `security.lsm = [ ... "bpf" ... ];` in NixOS host configurations, mandate `kernel.unprivileged_bpf_disabled = 1;` sysctl restrictions, detect abnormal socket creation bursts (> 250 sockets/sec) indicative of raw socket floods or C2 beaconing, synthesize declarative NixOS systemd `SystemCallFilter` modules with native architectures, and actively correlate kernel BPF verifier race conditions against live CVE advisories (CVE-2026-90412).
20. **Post-Quantum Cryptography (PQC) & CNSA 2.0 Cryptographic Readiness Invariants**: Declarative control plane scanners and runtime TLS telemetry auditors enforce strict memory and streaming bounds (10MB manifest ceiling, 5MB telemetry payload ceiling, 20,000 scan lines), mandate `--tls-min-version=VersionTLS13` on all Kubernetes control plane components (kube-apiserver, etcd, kubelet), prohibit weak classical cipher suites (CBC mode, 3DES, RC4, static RSA), mandate 256-bit symmetric encryption (`TLS_AES_256_GCM_SHA384`) and SHA-384/SHA-512 digests to satisfy NSA CNSA 2.0 quantum resistance mandates, detect missing hybrid post-quantum key encapsulation (`X25519MLKEM768`, `SecP384r1MLKEM1024`, NIST FIPS 203) exposing control plane links to Harvest-Now-Decrypt-Later (HNDL) quantum cryptanalysis (CVE-2026-94301), audit NixOS host OpenSSL configuration for `oqsprovider` activation and default quantum-safe groups, audit GnuTLS priority strings, detect etcd peer transport lacking quantum-safe mutual TLS, flag deprecated pre-standard draft parameter sets, and synthesize declarative NixOS modules (`pqc-hardened.nix`) and Kubernetes static pod manifests ensuring seamless post-quantum migration.
21. **Ephemeral MicroVM Sandbox & Honeypot Detonation Isolation Invariants**: Ephemeral microVM configuration scanners, detonation dispatch engines, and runtime telemetry analyzers enforce strict bounds limits (10MB manifest ceiling, 5MB telemetry payload ceiling, 20,000 scan lines, 1000 detonation batch limit), mandate Firecracker hypervisor execution with unprivileged jailer daemon confinement and chroot sandboxing (`jailer.enable = true;`), enforce hardware virtualization acceleration (`/dev/kvm`), mandate read-only root filesystem mounts (`readOnly = true;`) to prevent guest binary or Nix store tampering, require isolated TAP network devices (`isolateEgress = true;`) with strict default-drop egress rules to neutralize command-and-control (C2) beaconing vectors (CVE-2026-97105), redirect suspicious network connections to internal decoy honeypot sinks (emulated Kubelet port 10250 and etcd peering port 2379/2380), intercept synthetic canary credential harvesting attempts, detect runtime kernel syscall anomalies (reverse shells, `ptrace`, `bpf`, `setuid`), enforce a 30-second detonation SLA timeout to catch anti-sandbox stalling evasion, and synthesize declarative NixOS microVM modules (`microvm-sandbox.nix`) and Kubernetes `DetonationJob` specifications ensuring automated quarantine and isolation.

## Reporting a Vulnerability

If you discover a potential security issue, memory safety bug, or threat model flaw:

1. **Do not open a public issue** with exploit details before a fix is available.
2. Report the finding via [GitHub Security Advisories](../../security/advisories/new) or contact the maintainers directly with a minimal reproduction case.
3. We review reports promptly and coordinate fixes and release notes upon resolution.
